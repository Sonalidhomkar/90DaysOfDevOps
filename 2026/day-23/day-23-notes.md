# Day 23 – Git Branching & Working with GitHub 🚀
## 📌 What I LearneToday, I learned the basics of Git branching and how to work with GitHub.

### 1. What is a Git Branch?
A branch is an independent line of development that allows us to work on new features without directly affecting the main branch.

### 2. Why Do We Use Branches?
Branches help developers work independently, test new features, fix bugs, and keep the main branch stable.

### 3. What is HEAD?
HEAD is a reference that points to our current position in the Git repository.

### 4. Git Branching Commands

```bash
git branch
git branch feature-1
git switch feature-1
git switch -c feature-2
git switch main
git branch -a
git log --oneline --graph --all
```

### 5. What is Git Push?
`git push` uploads local commits to a remote repository such as GitHub.

```bash
git push -u origin main
git push -u origin feature-1
```

### 6. Git Fetch vs Git Pull
- **Git Fetch:** Downloads updates from a remote repository without automatically integrating them into the current branch.
- **Git Pull:** Fetches remote updates and integrates them into the current branch.

### 7. Clone vs Fork
- **Clone:** Creates a local copy of a repository on your computer.
- **Fork:** Creates a separate copy of a repository under your GitHub account.

### 8. What are Origin and Upstream?
- **Origin:** Commonly refers to your own remote repository.
- **Upstream:** Commonly refers to the original repository when working with a fork.

## 🎯 Key Takeaway

Git branching helps developers manage changes efficiently, while GitHub makes collaboration and version control easier.
